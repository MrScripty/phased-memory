# Evaluation protocol

This page owns the authored application schema and Rust metrics. The recovered original pack uses [a separate typed JSONL adapter and its preserved Python scorer](original-fixtures.md); its original labels and metric arithmetic are unchanged.

## Stage A: normalized directed pairs

Input `PairCase[]`: `{id,a:Claim,b:Claim,expected:Labels}`. `run_pairs` projects only `a` and `b` to the decision adapter. Neither case ID nor expected labels enter the inference prompt. Claim IDs/source fields must also be neutral; authored fixtures use neutral local IDs and semantic source text. Inspect any imported corpus for label leakage before real evaluation. `PairPrediction[]` contains `{id,labels:null|Labels,error:null|string,provenance:null|Provenance,native_probabilities:null|NativeProbabilities}`; exactly one labels/error is required.

Metrics: relationship accuracy; macro-F1 over all four fixed classes (absent classes score zero); expected-row/predicted-column confusion including `missing`; temporal accuracy; update accuracy; joint exact-label accuracy. All use the complete case denominator. Unknown IDs, duplicate IDs, malformed labels and inconsistent success/error records are rejected.

Brier is optional and reported only when **every** gold case has a complete finite nonnegative native probability vector summing to one within 1e-6, Pumas provenance and operator-supplied native-evidence reference. Duplicate/unknown probability keys are rejected at decoding. Multiclass Brier is the mean sum of four squared class errors, range [0,2]. `native_evidence` is an operator evidence reference, not automatically verified attestation. The inspected generation API does not expose native probabilities; this prototype's inference runner always emits null and cannot establish native evidence. Do not populate this field with generated confidence or self-reported JSON probabilities. Brier coverage is shown even when the full metric is unavailable. Scorer fixtures with authored probability values only test arithmetic.

## Stage B: extraction followed by decisions

Input `RawPairCase[]`: `{id,a_raw,b_raw,expected:Labels}`. Gold is not passed to extraction or decisions. Each side has independent extracted claims/error/provenance in `ExtractionRecord`. Extraction failure remains distinct from decision failure. Exactly one extracted claim per side is required for automatic pair alignment; multi-claim outputs are retained and marked alignment unavailable rather than selecting a convenient first claim. Decision success without two singly aligned successful extractions is rejected. Extraction coverage/failures, multi-claim count and the complete pair metrics are separate. Missing records and failed extraction remain failures in the full denominator. This reports end-to-end label performance, not an unimplemented claim-alignment or extraction-semantic-accuracy oracle.

## Stage C: retrieval

Input `RetrievalCase[]`: `{id,query_text,filters,expected_ids,misleading_ids,chronology}`. Gold IDs are used only in the scorer. Predictions `{id,ranked_ids:null|[memory_id],error:null|string}`. Corpus IDs come from SQLite. Unknown/duplicate case or memory IDs and overlapping relevant/misleading gold are rejected. The CLI obtains query embeddings through Pumas; explicitly synthetic UI smoke does not substitute for this run.

Metrics: top-1 relevant accuracy, reciprocal rank of first relevant hit, recall@5 (relevant retrieved in five / all relevant), misleading@5 (misleading retrieved / five fixed slots), and chronology accuracy for cases specifying at least two ordered IDs. Chronology requires every specified ID present in the declared order; this prototype returns at most five results, so gold histories longer than five cannot pass. Fixtures encode equal-time IDs in stable-ID presentation order only. Real evaluations should omit equal-time pairs from strict chronology gold rather than claim an order. Missing/errored queries score zero for desirable metrics and **one** for misleading@5 (explicit pessimistic failure penalty); they never disappear from denominators. Low misleading@5 is meaningful only alongside coverage and recall.

Structured retrieval receives explicit metadata filters in addition to query text. It is a diagnostic comparison, not proof that symbolic representation outperforms vectors with equal information. Generic reranking sees all structured-eligible candidates before publishing five. Structured filtering can still exclude relevant records, so report that eligibility recall separately. The original-pack reranker instead sees all ten records regardless of its query-plan eligibility filters.

## Separate controlled phase experiment (implemented, opt-in; live comparison unrun)

Phase encoding is a distinct opt-in CLI experiment: [commands, input, frozen mapping and evidence limits](phase-control.md). It is not enabled by the ordinary UI. Freeze one normalized corpus and one semantic feature list, including directed subject/predicate/object, polarity, perspective, continuity, story-time and qualifiers, before testing. Serialize that **same semantic information** as text for the embedding comparator and as explicit features for the phase arm. Separate raw-text embedding and extraction improvements from representation effects.

The frozen first experiment is an **expected-equivalence negative control**, not a phase advantage claim. Freeze these rules before any run:

1. Build a lexicographically ordered categorical vocabulary from the frozen corpus and query semantic inputs, with no gold labels. Each directed tuple key is `(subject,predicate,object,perspective,continuity)`; swapping subject/object changes the slot. Entity and qualifier sets are deduplicated/sorted for both features and Pumas JSON, and have their own prefixed slots. `state_key` and named timeline keys have separate prefixed slots. Unknown fields retain literal unknown categories.
2. At a tuple slot, affirmed polarity contributes complex value `1+0i`, negated contributes `-1+0i`, unknown contributes `0+1i`. Entity, qualifier, state-key and timeline presence contribute `1+0i` at their respective slots. No confidence is used. Unknown story time contributes an explicit unknown-time slot. Known position contributes a separate real scalar in the named timeline's numeric slot, divided by `T=max(1,max(abs(position)))` over the frozen semantic inputs; retain the integer and timeline in the source authority. Time never becomes an angle or ingestion ordering.
3. Normalize each nonzero complex vector by its Euclidean norm. Rank by `Re(sum(conj(query_j)*memory_j))`, breaking ties by claim ID. The exact same-information numeric comparator concatenates real and imaginary channels `[Re(z),Im(z)]`, applies ordinary cosine, and uses the same tie rule. Their scores **must agree within 1e-12** in f64 arithmetic; disagreement is an implementation failure. This expected-equivalence result cannot establish a benefit of phase representation.
4. A separate Pumas embedding comparator receives canonical sorted-key JSON of exactly these semantic inputs (directed triple, polarity, entities, qualifiers, perspective, continuity, state key and story time). It receives no raw prose or hidden labels unavailable to the phase arm. Its semantic information is held constant, although the learned embedding operation differs from the numeric control. Freeze its exact model/profile/runtime identity and resulting space before scoring.

The numeric control and same-information Pumas comparator are implemented in `phase.rs`. Deterministic arithmetic and boundary regressions verify the control; real model comparison remains unrun until an operator supplies a compatible model/runtime. Any non-equivalent kernel, phase interaction or feature weighting is a new experiment requiring its own frozen rules before results. The real-concatenation identity supplies an independent arithmetic oracle; it supplies no semantic-quality oracle. The 1e-12 obligation is score equivalence only: raw near-tie rankings may differ from floating-point arithmetic and are reported without repair.

Use identical train/dev/test partitions, query semantics, candidate pool, metadata availability and denominators for both arms; label access stays with scorers. Evaluate both representations on the same Stage C gold, plus direction swaps, negation, perspective conflicts and temporal history controls. Report bootstrapped uncertainty only after a real sufficiently sized frozen corpus exists. No acceptance threshold, phase benefit or native probability claim can be inferred from authored synthetic vectors or the original development ZIP. The runtime operator owns model qualification and the resulting reproducibility report.
